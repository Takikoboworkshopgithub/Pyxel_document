# Introduction

この章では、「クラス」について学びます。

クラスとは一言で言えば、「関連するデータと、それを操作する処理をひとまとめにする仕組み」です。

クラスの概念は、Pythonを始め、C++やJavaなどのモダンなプログラミング言語に付随しています。大規模な開発で活きる概念なので、ぜひ使いこなしましょう！


さて、ゲームのPlayerを作ります。Playerは「名前」「HP」「攻撃力」というデータと、「攻撃する」「回復する」という処理も行います。

これを一つのまとまりとして扱うのがクラスの考え方です。

2.1 C++の構造体を振り返る

C++を用いてPlayerクラスを作ってみましょう。

C++
#include <bits/stdc++.h>
using namespace std;

// 構造体の定義
struct Player {
    string name;
    int hp;
    int attack;
};

int main() {
    // 構造体変数 alice の作成
    Player alice;

    // メンバへのアクセス
    alice.name = "Alice";
    alice.hp = 100;
    alice.attack = 20;

    cout << alice.name << "のHPは" << alice.hp << endl;
    return 0;
}
  • struct を使うと、Playerに関係するデータをひとまとめにできます。
  • name, hp, attack は「メンバ」と呼ばれます。
  • alice はそこから作られた「構造体変数」です。
  • alice.hp のように「. (ドット)」を使ってメンバへアクセスします。

構造体の問題提起：処理はどこに書く？

構造体を使うと「データ」はまとめられます。
しかし、「そのデータを操作する処理」はどうなるでしょうか？
例えば、Playerを回復させる heal 関数を作ると、次のようになります。 


#include <bits/stdc++.h>
using namespace std;

struct Player {
    string name;
    int hp;
    int attack;
};

// Playerのデータを操作する関数（構造体の外にある）
void heal(Player& player) {
    player.hp += 10;
}
int main() {

    Player alice;

    alice.name = "Alice";
    alice.hp = 100;
    alice.attack = 20;

    cout << alice.name << "のHPは" << alice.hp << endl;
    return 0;
}

データは Player の中にまとまっているのに、処理である heal は外側にポツンと置かれています。
これでは、「Playerに関係するデータと処理がバラバラになっている」状態です。

「このバラバラな状態を解決し、Playerに関係する処理もまとめてしまおう！」というのが、Pythonのクラスです。

2.2 Pythonのクラス

細かい文法を一つずつ覚える前に、まずは完成形のPythonコードを見てみましょう。
一つずつ分解して見ていきます

Python (完成形)
class Player:
    def __init__(self, name, hp, attack):
        self.name = name
        self.hp = hp
        self.attack_power = attack

# クラスからオブジェクトを作る (具体的な名前をつける)
alice = Player("Alice", 100, 20)
bob = Player("Bob", 150, 30)

# データの確認
print(alice.name)          # 出力: Alice
print(alice.hp)            # 出力: 100
print(alice.attack_power)  # 出力: 20

print(bob.name)            # 出力: Bob

Pythonでは class クラス名: と書くことでクラスを定義します。今回の学習では、C++の struct に対応するものだと考えてください。

C++
struct Player {
    ...
};
Python
class Player:
    ...

2.2.2 __init__

__init__ (イニシャライズの略) は、オブジェクトを作ったときに最初に自動で呼ばれる初期化処理です。前後のアンダースコアは2つずつ（ _ _ init _ _ ）であることに注意してください。 

    def __init__(self, name, hp, attack):
        self.name = name
        self.hp = hp
        self.attack_power = attack

alice = Player("Alice", 100, 20) と実行したとき、引数が次のように渡されます。

2.2.3 属性

self.name や self.hp は、そのオブジェクトが持っているデータのことです。これをPythonでは「属性 (Attribute)」と呼びます。C++のメンバ変数 alice.name に相当します。

2.2.4 クラスを使う

クラスは設計図にすぎません。実際に使うには alice = Player(...) のように実体を作ります。
同じ Player クラスから、Alice と Bob という全く別のデータを持ったキャラクターを作ることができます。

2.3 self

Pythonのクラスを学ぶ上で、最もつまずきやすいのが self です。
「self ＝ 今操作している、そのオブジェクト自身」のことです。

selfとは何か

alice = Player("Alice", 100, 20) で作られたデータを操作しているとき、self.name は alice.name になります。
bob = Player("Bob", 150, 30) で作られたデータを操作しているとき、self.name は bob.name になります。

なぜselfが必要なのか

    def __init__(self, name):
        # self.name と name は別物！
        self.name = name
# self.name に name = "Alice" が入る
alice = Player("Alice")
  • 右辺の name は、引数として外から受け取った値 ("Alice" など) です。
  • 左辺の self.name は、オブジェクト自身が持つ属性（データ保存用の箱）です。

「受け取った値(name)を、自分自身のデータ(self.name)として記憶する」という意味になります。

TRY 2

さきほどのコードに、3人目のキャラクター charlie を追加してみましょう。
HPや攻撃力は好きな数値に設定し、print で正しくデータが設定されているか確認してください。

2.4 メソッド

2.1節で、C++の構造体では「データ」はまとめられても「処理」が外に出てしまうという問題がありました。
Pythonのクラスでは、クラスの中に処理を書くことができます。これを「メソッド」と呼びます。

関数と同じ概念ですが、クラス内に書かれた関数を「メソッド」と呼びます。

class Player:
    def __init__(self, name, hp, attack):
        self.name = name
        self.hp = hp
        self.attack_power = attack

    # 回復するメソッド
    def heal(self):
        self.hp += 10
        print(f"{self.name}は回復した！ HPが {self.hp} になった。")

    # 攻撃するメソッド
    def attack(self, damage):
        print(f"{self.name}が{damage}のダメージを与えた！")

# 実行部分
alice = Player("Alice", 100, 20)

# メソッドの呼び出し
alice.heal()
alice.attack(15)

alice.heal() と呼び出すと、heal(self) の self には alice 自身が自動的に渡されます。
つまり、「alice自身のhpを10増やす」という処理が行われます。

属性名とメソッド名の衝突に注意

上記のコードで、攻撃力というデータ（属性）を self.attack_power とし、攻撃する処理（メソッド）を attack() としています。
もし属性も self.attack にしてしまうと、「データとしての攻撃力」と「処理としての攻撃」の名前が被ってしまい、Pythonが混乱してエラーになることがあります。
「データ」と「処理」は別物であることを意識して名前を付けましょう。

TRY 3

上記のコードを実行し、alice.heal() を2回連続で呼び出してみましょう。
HPが100 → 110 → 120と正しく増えていくことを確認してください。

2.5 データと処理をまとめる

なぜクラスが必要なのでしょうか？ クラスを使わない場合と使った場合を比較してみましょう。

クラスを使わない場合（データと処理がバラバラ）

もし変数だけでゲームを作ろうとすると、キャラクターが増えるたびに変数が大量に増え、誰のデータをどの関数が処理しているのか人間が頭の中で管理しなければなりません。 

# データがバラバラ
player1_hp = 100
player1_attack = 20
player2_hp = 150
player2_attack = 30

# 処理もバラバラ
def player1_heal():
    global player1_hp
    player1_hp += 10

クラスを使った後（カプセル化）

クラスを使うと、「このデータと処理はセットだよ」ということが明確になります。
「誰のデータを、どの処理が操作するのか」が自動的に整理されるのです。

2.6 複数のオブジェクト

最後に、同じクラスから複数のキャラクターを作って動かしてみましょう。 

# 前節と同じPlayerクラスを使います

alice = Player("Alice", 100, 20)
bob = Player("Bob", 150, 30)

print(f"回復前: Alice HP={alice.hp}, Bob HP={bob.hp}")

# aliceだけが回復する
alice.heal()

print(f"回復後: Alice HP={alice.hp}, Bob HP={bob.hp}")

これを実行すると、alice.heal() を呼んだことで alice.hp は 110 になりますが、bob.hp は 150 のままであることがわかります。
「selfはそのオブジェクト自身」なので、Aliceが回復してもBobのHPには影響しないのです。

💡 オブジェクトという用語

ここで正式なプログラミング用語を一つ覚えておきましょう。
・Player → クラス (設計図)
・alice や bob → オブジェクト (設計図から作られた実体)
※オブジェクトの代わりに「インスタンス」と呼ぶこともあります。意味はほぼ同じです。
