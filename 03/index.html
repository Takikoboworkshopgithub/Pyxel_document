# Introduction

第2章では、Pythonにおけるクラスの文法（class, __init__, self, 属性, メソッド）を学びました。

第3章では、これらの文法を使って、「ゲームの登場人物やアイテムなどの要素を、クラスを使ってどのように捉え、どのように設計していくか」というプログラミングの「設計思想（設計の考え方）」を学びます。

ゲームの中には、プレイヤー、敵キャラ、武器、回復アイテム、弾丸など、様々な要素が存在します。これらの要素を「状態（データ）を持ち、それに応じた動作（処理）を行うもの」として捉え、クラスとして設計していくことが重要です。

3.1 ゲームの登場人物をクラスにする

ゲームを作るとき、画面の中には様々な要素が存在します。 例えば、プレイヤー、敵キャラ、武器、回復アイテム、弾丸などです。これらはすべてプログラム上で管理する必要があります。

3.1.1 Player

まずは2章で学んだクラスを使って、ゲームの主人公である Player を作成します。

Python
class Player:
    def __init__(self, name, hp, attack_power):
     self.name = name
     self.hp = hp
     self.attack_power = attack_power

    def attack(self):

# Playerのインスタンス（オブジェクト）を作成
Alice = Player("Alice", 100, 20)

3.1.3 「もの」をクラスにする

そもそも、なぜこれらがクラスになるのでしょうか。ゲームの中に存在する「もの」をプログラムに落とし込む思考プロセスを図で整理してみましょう。

ゲームの中に存在する「状態（データ）を持ち、それに応じた動作（処理）を行うもの」は、クラスとして表現するのに完璧な対象です。

3.2 Characterクラスを作る

先ほど比較した通り、Player と Enemy には全く同じ属性（name, hp, attack_power）と全く同じメソッド（attack()）が含まれています。

プログラミングの大原則は DRY原則（Don't Repeat Yourself：同じコードを繰り返さない） です。「ほとんど同じコードを2回書いている」のは設計上の大きな問題であり、変更やバグの修正が2倍大変になってしまいます。

3.2.1 Character

そこで、両者に共通する仕組みをまとめた親となるクラス Character を作成します。

3.2.2 継承

ここで登場するのが「継承（Inheritance）」です。
Pythonでは、クラス名の後ろに class 子クラス名(親クラス名): と書くことで、親クラスの機能（属性・メソッド）をすべて引き継ぐことができます。

まずは pass（「何も追加処理をしない」を意味するキーワード）を使って、本当に機能が受け継がれるか確認してみましょう。

Python
# 親クラス（スーパークラス）
class Character:
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.hp = hp
        self.attack_power = attack_power

    def attack(self):
        print(self.name, "の攻撃！")

# 子クラス（サブクラス）: Characterの機能を持つ
class Player(Character):
    pass

class Enemy(Character):
    pass

# 実証してみよう
Alice = Player("Alice", 100, 20)
Slime = Enemy("Slime", 50, 10)

Alice.attack()  # 出力: Alice の攻撃！
Slime.attack()  # 出力: Slime の攻撃！

Player や Enemy の中身は pass だけなのに、Character で定義した __init__ や attack() が問題なく動作しました！

3.2.3 共通する属性

継承の真価は、「共通の属性・メソッドは親クラスに任せ、子クラスには固有の機能だけを書く」という役割分担にあります。

継承を使って実装する

先ほどの図を実際のコードにすると、次のようになります。 Character に共通する属性やメソッドをまとめ、 Player と Enemy には、それぞれ固有の処理だけを追加します。

Python 
# 親クラス
class Character:
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.hp = hp
        self.attack_power = attack_power

    # Characterに共通するメソッド
    def attack(self):
        print(self.name, "の攻撃！")


# PlayerはCharacterを継承する
class Player(Character):
    def move(self):
        print(self.name, "が移動した！")


# EnemyもCharacterを継承する
class Enemy(Character):
    def chase_player(self):
        print(self.name, "がプレイヤーを追いかける！")


# Player
Alice = Player("Alice", 100, 20)

# Characterから受け継いだ属性・メソッド
print(Alice.hp)
Alice.attack()

# Player独自のメソッド
Alice.move()


# Enemy
Slime = Enemy("Slime", 50, 10)

# Characterから受け継いだ属性・メソッド
print(Slime.hp)
Slime.attack()

# Enemy独自のメソッド
Slime.chase_player()

POINT

  • name、hp、attack_power は Character にまとめる。
  • attack() も Character にまとめる。
  • Player は move() だけを追加する。
  • Enemy は chase_player() だけを追加する。

このように、共通する部分を親クラスにまとめ、異なる部分だけを子クラスに追加する ことで、同じコードを何度も書かずに済みます。

3.2.4 共通するメソッド

attack() のような共通動作を Character に配置しておくことで、「プレイヤーも敵も、キャラクターの一種として同じように攻撃できる」という一貫性が生まれます。

Player クラスにだけ def move(self): print(self.name, "は移動した。") を追加してみましょう。Alice.move() は呼び出せるが、Slime.move() を呼ぶとエラーになることを手元で確かめてみましょう。

3.3 オブジェクトを管理する

単体のクラスが作れるようになったら、次は「大量のオブジェクトをどう管理するか」というステップに進みます。

3.3.1 リストとクラス

ゲームに敵が10匹、100匹と登場するとき、変数を1つずつ手動で作るのは不可能です。 

# これは管理が大変...
enemy1 = Enemy("Slime", 30, 5)
enemy2 = Enemy("Goblin", 50, 10)
enemy3 = Enemy("Dragon", 200, 30)

Pythonのリストには、数値や文字列だけでなく「オブジェクトそのもの」を格納することができます。

Python
enemies = [
    Enemy("Slime", 30, 5),
    Enemy("Goblin", 50, 10),
    Enemy("Dragon", 200, 30)
]

3.3.2 複数のEnemy

enemies リストの中に複数の Enemy オブジェクトが格納されているイメージは以下の通りです。

3.3.3 forでまとめて処理

「リスト ＋ for ループ ＋ クラス」を組み合わせることで、どれほど大量のオブジェクトが存在していても、わずか数行でまとめて処理を行えます。

Python
# 全員の名前を表示
for enemy in enemies:
    print(enemy.name)

# 全員に一斉に攻撃行動を行わせる
for enemy in enemies:
    enemy.attack()

3.3.4 オブジェクトの追加・削除

ゲームの進行に伴って新しい敵が出現した場合は append()、倒されて消滅した場合は remove() などを使ってリストから外します。

Python
# 新しい敵「Bat」が途中出現
enemies.append(Enemy("Bat", 20, 3))

# 先頭の敵（Slime）が倒れたのでリストから除外
defeated_enemy = enemies[0]
enemies.remove(defeated_enemy)
# または del enemies[0]

3.4 メソッド同士を連携させる

これまでは「1つのオブジェクトが単体で動作する」例だけを見てきましたが、実際のゲームでは「オブジェクト同士が影響し合う」処理が不可欠です。

3.4.1 PlayerからEnemyを操作

例えば、「AliceがSlimeを攻撃する」という処理は、Alice.attack(Slime) のように攻撃対象のオブジェクトを引数として渡すことで実現します。

3.4.2 攻撃

Character クラスの attack メソッドを拡張し、受け取った対象（target）のHPを自身の攻撃力分減らすように書き換えます。 

    def attack(self, target):
        target.hp -= self.attack_power

ここで引数 target は、攻撃対象となる「他のCharacterオブジェクト」を指します。

3.4.3 ダメージ

実際にメッセージ表示を含めた完全なプログラムを実行してみましょう。

Python
class Character:
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.hp = hp
        self.attack_power = attack_power

    def attack(self, target):
        target.hp -= self.attack_power
        print(f"{self.name}が{target.name}に{self.attack_power}のダメージ！")

class Player(Character):
    pass

class Enemy(Character):
    pass

Alice = Player("Alice", 100, 20)
Slime = Enemy("Slime", 30, 5)

print("攻撃前のSlime HP:", Slime.hp)  # 30
Alice.attack(Slime)
print("攻撃後のSlime HP:", Slime.hp)  # 10

3.4.4 オブジェクト同士の関係

オブジェクト指向設計では、「単一のオブジェクトをどう作るか」だけでなく、このように「オブジェクト同士がメッセージ（メソッド呼び出し）を通じてお互いの状態を変化させる」という視点が非常に重要になります。

3.5 オブジェクトの状態を管理する

オブジェクトは内部に「状態（State）」を持っています。ゲームプログラムでは、オブジェクトの現在の状態に応じて処理を分岐させることが一般的です。

3.5.1 HP / 3.5.2 生存・死亡

キャラクターの最も基本的な状態は「生存」と「死亡」です。これは hp の値によって移り変わります。

3.5.3 is_alive()

if enemy.hp > 0: と直接判定を書くこともできますが、生存条件の判定を is_alive() というメソッドとしてカプセル化（定義）しておくと、設計上非常に大きなメリットがあります。

Python
class Character:
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.hp = hp
        self.attack_power = attack_power

    # 生存判定を行うメソッド
    def is_alive(self):
        return self.hp > 0

💡 設計上のポイント（カプセル化）
もし将来「毒状態ならHP1でも死亡扱い」「食いしばりスキルがあればHP0でも1回生存」のように生存条件の仕様が変わっても、is_alive() の中身だけを修正すればよく、呼び出し側のコードを変更する必要がなくなります。

3.5.4 状態に応じた処理

リスト管理と組み合わせることで、「生きている敵だけが攻撃してくる」という実践的なゲームループが構築できます。

Python
# 生きている敵だけが行動するループ
for enemy in enemies:
    if enemy.is_alive():
        enemy.attack(Alice)
    else:
        print(f"{enemy.name}は倒れている...")

TRY 3.5

ここまでのコードを一つにまとめる

ここまで学んだ内容を、一つのプログラムにまとめてみましょう。 このコードでは、Character、継承、リストによるオブジェクト管理、 オブジェクト同士の攻撃、HPによる状態管理をすべて使用しています。

このコードで使っていること

  • Character に共通するデータと処理をまとめる
  • Player と Enemy が Character を継承する
  • Enemy オブジェクトをリストでまとめて管理する
  • attack(target) でオブジェクト同士が影響を与える
  • is_alive() でキャラクターの状態を判定する
Python 
# ==============================
# Characterクラス
# ==============================

class Character:
    def __init__(self, name, hp, attack_power):
        self.name = name
        self.hp = hp
        self.attack_power = attack_power

    # 攻撃する
    def attack(self, target):
        target.hp -= self.attack_power
        print(
            f"{self.name}が{target.name}に"
            f"{self.attack_power}のダメージ！"
        )

    # 生存しているか判定する
    def is_alive(self):
        return self.hp > 0


# ==============================
# Playerクラス
# Characterを継承
# ==============================

class Player(Character):
    def move(self):
        print(f"{self.name}が移動した！")


# ==============================
# Enemyクラス
# Characterを継承
# ==============================

class Enemy(Character):
    def chase_player(self):
        print(f"{self.name}がプレイヤーを追いかける！")


# ==============================
# オブジェクトを作成
# ==============================

Alice = Player("Alice", 100, 40)

enemies = [
    Enemy("Slime", 30, 5),
    Enemy("Goblin", 50, 10),
    Enemy("Dragon", 200, 30)
]


# ==============================
# Playerの行動
# ==============================

Alice.move()


# ==============================
# 敵の一覧を表示
# ==============================

print("=== 敵の一覧 ===")

for enemy in enemies:
    print(
        enemy.name,
        "HP:", enemy.hp,
        "攻撃力:", enemy.attack_power
    )


# ==============================
# AliceがSlimeを攻撃
# ==============================

print("\n=== 戦闘開始 ===")

Slime = enemies[0]

Alice.attack(Slime)

print("Slimeの残りHP:", Slime.hp)


# ==============================
# 生きている敵がAliceを攻撃
# ==============================

print("\n=== 敵のターン ===")

for enemy in enemies:
    if enemy.is_alive():
        enemy.attack(Alice)
    else:
        print(f"{enemy.name}は倒れている...")


# ==============================
# 現在の状態を確認
# ==============================

print("\n=== 現在の状態 ===")

print(f"{Alice.name}のHP:", Alice.hp)

for enemy in enemies:
    status = "生存" if enemy.is_alive() else "死亡"

    print(
        f"{enemy.name}: "
        f"HP={enemy.hp}, {status}"
    )

3.6 ゲームを設計してみよう

ここまでの内容をふまえ、今度はあなた自身が「オリジナルゲームのクラス設計」に挑戦してみましょう。プログラムのコードを書く前に、設計図を描くワークショップです。

3.6.1 登場する「もの」を考える

自分が作りたいゲームジャンル（例：2Dシューティング、コマンドRPG、アクション等）を1つ思い浮かべ、そこにどんな「もの」が登場するか書き出してみましょう。

  • シューティングゲームの例： Player, Enemy, Bullet（自機弾/敵弾）, Item
  • RPGの例： Player, Enemy, Weapon, Item, Party

3.6.2 属性を考える

抽出した「もの」が、それぞれどのようなデータ（属性）を持つべきか整理します。

Player の属性（例）

├── name (名前)
├── hp (体力)
├── x, y (画面上の位置座標)
└── attack_power (攻撃力)

Bullet (弾) の属性（例）

├── x, y (現在位置)
├── speed_x, speed_y (移動速度)
└── power (威力)

3.6.3 メソッドを考える

次に、各オブジェクトが行える処理（メソッド）を考えます。

・属性 ＝ そのものが持っているデータ（名詞的）

・メソッド ＝ そのものができる処理（動詞的）
