5. ゲームを作ろう

Python + Pyxelでシューティングゲームを作りながら、オブジェクト指向的な設計を学ぶ

この章の重要なお知らせ

この章では、単にコードを写してゲームを完成させることだけを目的にしません。

「ゲームを実装するには、何をオブジェクトとして扱う必要があるのか」「それぞれのオブジェクトは何を知っているべきなのか」「どの処理を誰の責務にするべきなのか」
という「設計」の考え方を身につけることを重視します。

# Introduction

これまでPythonの基本文法やリスト、関数、そして「クラス」について学んできました。今回はそれらの知識を総動員して、PythonとPyxelを使った「シューティングゲーム」を段階的に制作します。

この章では、ゲームの見た目を作るだけでなく、ゲームの中に存在するものをどのようにクラスとして整理し、責務をどのように分けるかを考えていきます。

次週では、各々でPyxelのゲームを制作する回になります。今回は、実際にゲームを制作する際にどのような手順で設計するかについて、シューティングゲームを題材に考えていきましょう。

5.1 最小のゲームを作る

まずはシューティングゲームとして最低限必要な要素を整理してみましょう。

  • プレイヤーを動かす
  • 敵を置く
  • 弾を発射する
  • 当たり判定を行う
  • 敵を倒す

クラスを一切使わず、手続き型のプログラムとして「プレイヤーを左右に動かすだけ」のコードを書くと、以下のようになります。

Python
import pyxel

x = 80
y = 100

def update():
    global x
    if pyxel.btn(pyxel.KEY_LEFT):
        x -= 2
    if pyxel.btn(pyxel.KEY_RIGHT):
        x += 2

def draw():
    pyxel.cls(0)
    pyxel.rect(x, y, 8, 8, 9)

pyxel.init(160, 120)
pyxel.run(update, draw)

このように手続き型でコーディングすることも可能ですが、ここに「敵10体」「それぞれのHP」「弾丸50発」が追加されたらどうなるでしょうか？ 無数の global 変数と、巨大な update() 関数ができあがり、すぐにコードの修正が困難（スパゲッティコード）になってしまいます。
複雑なゲームを作るためには、「何が必要なのか」を見極め、役割ごとにプログラムを分割する必要があります。

関数・構文の復讐

  • pyxel.init(width, height) : Pyxelの画面を初期化します。今回は幅160、高さ120の画面を作ります。
  • pyxel.run(update, draw) : ゲームループを開始します。Pyxelは自動的に update() と draw() を繰り返し呼び出します。
  • pyxel.btn(key) : 指定されたキーが押されていれば True を返します。
  • pyxel.KEY_LEFT / pyxel.KEY_RIGHT : 左キーと右キーを表す定数です。
  • pyxel.cls(color) : 画面を指定した色（0は黒）でクリアします。
  • pyxel.rect(x, y, w, h, color) : 指定した位置に矩形（四角形）を描画します。

Pyxelのゲームループ構造

「計算」と「描画」は明確に分離されています。

5.2 ゲームをどう設計するか

ここがこの章で最も重要なパートです。まずは「誰に何を任せるか」という責務分担を考えます。

責務分担を考えてみよう！

シューティングゲームを作るとき、以下の処理はどのオブジェクトが担当するべきでしょうか？

  • プレイヤーの位置は誰が管理する？
  • プレイヤーのHPは誰が持つ？
  • 敵の位置は誰が管理する？
  • 弾丸の位置は誰が管理する？
  • 弾丸が敵に当たったかどうかは誰が判定する？
  • 敵が倒れたことは誰が判断する？
  • 倒した敵の数を誰が数える？
  • ゲームオーバーになったかどうかは誰が判断する？

5.2.1 必要なクラスを考える

このゲームには、どんな「存在」が必要でしょうか。現実世界に例えて考えてみましょう。

プレイヤーはプレイヤー自身の位置やHPを把握しているのが自然です。敵も同じですね。弾丸も、自分自身の位置と飛んでいく速度を持っているのが自然です。
では、「ゲーム全体のスコア」や「ゲームオーバーかどうかの判定」はどうでしょうか？ プレイヤーが知っているのは少し不自然ですし、敵が知っているのも変です。

そこで、ゲーム全体を神の視点から俯瞰し、管理する存在が必要になります。ここではそれを GameMaster と呼ぶことにしましょう。これにより、必要なクラスの候補が見えてきます。

  • Player
  • Enemy
  • Bullet
  • GameMaster

5.2.2 各クラスの責務を考える

次に、先ほどの問いに対する「設計の答え」を考えてみます。設計に「絶対にこれしかない」という正解はありませんが、今回は以下のように責務（責任を持って処理する範囲）を分担してみましょう。

特に重要なのは「誰がHIT判定（当たり判定）をするのか」という問題です。
Playerが判定する？ Enemyが判定する？ Bulletが判定する？
当たり判定は「弾丸」と「敵」という別々のオブジェクト同士の位置関係を調整する処理です。もしBulletが判定する場合、Bulletは「すべてのEnemyの位置」を知らなければならず、コードが複雑に絡み合ってしまいます。
そこで今回は、すべてのオブジェクトのリストを管理している GameMaster に当たり判定の責務を持たせる設計にします。

5.2.3 責務分担の視覚化

それぞれのクラスが何を担当するのか、構造を図にしてみました。

5.2.4 メソッドを考える

それぞれのクラスの責務が決まったら、どんなメソッドを用意すればいいかを考えてみましょう。

例えば Player は、キーボード入力で移動し、スペースキーで弾を撃ちたい。だから move() と shoot() が必要になりそうです。また、すべてのオブジェクトはPyxelのゲームループに合わせて更新・描画される必要があるため、共通して update() と draw() を持つと統一感が出ます。

5.2.5 「可用性」という考え方 (ちょっと発展)

ここで「可用性（利用できる状態になっているか）」や「インターフェース」という考え方に触れておきましょう。
例えば、GameMaster が Player を移動させる時、GameMaster が直接 player.x -= 2 と書き換える設計にすることもできます。しかしこれだと、GameMaster は「Player は内部に x という変数を持っている」という内部の仕組みに依存してしまいます。

もし将来「Playerはx,y座標じゃなくて、ベクトルで管理しよう」と変更した場合、GameMaster側のコードも書き直さなければなりません。
そうではなく、Playerの中に move() というメソッドを用意し、GameMasterからは player.move() を呼び出すだけにします。こうすれば、移動の具体的な仕組みはPlayerの中に隠す（カプセル化する）ことができます。これも、責任の所在を明らかにできる重要な考え方です

5.2.6 可用性を表にする

「外部から操作できること（メソッド）」と、「内部で管理すべきデータ（属性）」を明確に分けましょう。

オブジェクト 外部から使う操作（メソッド） 内部で管理するもの（属性）
Player update(), draw(), move(), shoot() x, y, hp, speed, w, h
Enemy update(), draw() x, y, hp, speed, w, h
Bullet update(), draw() x, y, speed, w, h
GameMaster run(), update(), draw(), check_collision() score, game_state, 各種リスト

5.3 クラスを実装する

設計図ができたので、いよいよコードを書いていきます。段階的に追加していくことで、「なぜこのコードが必要なのか」を確認しましょう。

5.3.1 Playerクラス

まずは Player クラスです。初期化メソッド __init__ で属性を定義し、WASDキー（または方向キー）での移動を実装します。

Python
class Player:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        self.w = 8
        self.h = 8
        self.speed = 2
        self.hp = 3

    def move(self):
        if pyxel.btn(pyxel.KEY_LEFT) or pyxel.btn(pyxel.KEY_A):
            self.x -= self.speed
        if pyxel.btn(pyxel.KEY_RIGHT) or pyxel.btn(pyxel.KEY_D):
            self.x += self.speed
        if pyxel.btn(pyxel.KEY_UP) or pyxel.btn(pyxel.KEY_W):
            self.y -= self.speed
        if pyxel.btn(pyxel.KEY_DOWN) or pyxel.btn(pyxel.KEY_S):
            self.y += self.speed

    def update(self):
        self.move()

    def draw(self):
        # プレイヤーは緑色(11)の四角形
        pyxel.rect(self.x, self.y, self.w, self.h, 11)

クラスの設計通り、self.x や self.y を使って自分自身の状態を管理していますね。pyxel.KEY_A などはPyxel側であらかじめ用意されているキーボード定数です。

5.3.2 Bulletクラス

次に、弾丸クラスです。弾丸は生成された後、上に向かって飛んでいきます。

Python
class Bullet:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        self.w = 2
        self.h = 4
        self.speed = 4

    def update(self):
        # 上方向（yが減る方向）に移動
        self.y -= self.speed

    def draw(self):
        # 弾丸は黄色(10)
        pyxel.rect(self.x, self.y, self.w, self.h, 10)

ここで重要な問題に気づきます。「弾丸は1発ではなく、撃つたびに何発も増えていく」ということです。つまり、後で複数のBulletを管理する仕組みが必要になります。

5.3.4 GameMasterクラスの骨格

これらを取りまとめる GameMaster を作成します。Pyxelのシステム機能もここで呼び出します。

Python
class GameMaster:
    def __init__(self):
        pyxel.init(160, 120, title="Shooting Game")

        # プレイヤーを生成して保持
        self.player = Player(76, 100)

        # 敵や弾丸は複数あるので「リスト」で管理する
        self.enemies = []
        self.bullets = []

        # runを呼ぶとゲームループ開始
        pyxel.run(self.update, self.draw)

    def update(self):
        self.player.update()

        for bullet in self.bullets:
            bullet.update()

        for enemy in self.enemies:
            enemy.update()

    def draw(self):
        pyxel.cls(0) # 画面クリア
        self.player.draw()

        for bullet in self.bullets:
            bullet.draw()

        for enemy in self.enemies:
            enemy.draw()

# ゲーム起動
# game = GameMaster()

self.enemies = [] のように空のリストを用意し、for 文を使ってリストの中身すべてに対して update() や draw() を呼び出している点に注目してください。

5.4 オブジェクトを増やす

GameMasterの準備ができたので、実際にリストへオブジェクトを追加・削除する処理を実装します。

弾を撃つ（Player側からBulletを増やす）

スペースキーを押したときに弾を生成したいのですが、Bulletリストは GameMaster が持っています。そのため、少し工夫が必要です。GameMasterのupdate内で以下のように処理します。

Python
# GameMasterのupdate内に追加
if pyxel.btnp(pyxel.KEY_SPACE):
    # プレイヤーの中央から弾を生成
    new_bullet = Bullet(self.player.x + 3, self.player.y)
    self.bullets.append(new_bullet)

💡 新しい関数・構文の解説

  • pyxel.btnp(key) : btn()と違い、キーが「押された瞬間」だけ True になります。長押しで連続発射されるのを防ぎます。
  • list.append(要素) : Pythonのリストの末尾に、新しい要素を追加します。

不要になったオブジェクトを消す

画面外に出た弾丸や敵をいつまでもリストに残しておくと、メモリを無駄遣いし動作が重くなります。そのため、リストから削除する処理を update() に追加します。

Python
# 画面外に出た弾を削除
for bullet in self.bullets[:]: # リストのコピーを回す
    if bullet.y < -10:
        self.bullets.remove(bullet)

※ remove() はリストから指定した要素を削除するメソッドです。ループ中に要素を削除する際は [:] を使ってリストのコピーを回すのがPythonのセオリーです。

5.5 当たり判定

シューティングゲームの要である「当たり判定（Collision Detection）」です。今回は「矩形（四角形）」同士が重なっているかを判定します。

2つの四角形が重なっている条件は、以下の4つをすべて満たすことです。

Python
def check_collision(self):
    for enemy in self.enemies[:]:
        for bullet in self.bullets[:]:
            # 矩形同士の当たり判定
            if (bullet.x < enemy.x + enemy.w and
                bullet.x + bullet.w > enemy.x and
                bullet.y < enemy.y + enemy.h and
                bullet.y + bullet.h > enemy.y):

                # 当たった場合の処理
                enemy.hp -= 1
                self.bullets.remove(bullet)

                if enemy.hp <= 0:
                    self.enemies.remove(enemy)
                    self.score += 10 # GameMasterがスコアを管理

5.2の設計で決めた通り、この判定処理は特定のキャラクターではなく GameMaster に持たせています。それにより、リスト内の要素を自由にチェックしたり削除したり、スコアを加算したりすることが可能になっています。

5.6 ゲームらしくする

敵のランダム出現、ゲームオーバー、タイトル画面といった「ゲームの流れ（状態遷移）」を実装します。

ゲームの状態遷移（ステート）

ゲームは常にプレイ中なわけではありません。タイトル画面、プレイ画面、ゲームオーバー画面といった「状態」をGameMasterに管理させます。

GameMasterの __init__ で self.game_state = "TITLE" としておき、update と draw の中で if 文を使って処理を分岐させます。

💡 新しいモジュールと関数

  • import random : 乱数（ランダムな値）を扱うための標準モジュールを読み込みます。
  • random.randint(a, b) : a から b の範囲でランダムな整数を返します。
  • pyxel.frame_count : ゲーム開始から何フレーム経過したかを表す変数です。if pyxel.frame_count % 30 == 0: のように書くと一定間隔で処理できます。
  • pyxel.text(x, y, "文字", color) : 画面にテキストを描画します。

5.7 継承を使って設計を整理する

さて、ここまででゲームに必要な要素はほぼ出揃いました。しかし、Player クラスと Enemy クラスのコードを見比べてみてください。

どちらも x, y, w, h, speed, hp という属性を持ち、update() と draw() というメソッドを持っています。「同じようなコードを2回書く必要があるだろうか？」という疑問が湧きませんか？

ここで、前章で学んだ継承の出番です。共通する要素を Character クラスとして抽出し、それを継承することで設計を整理（リファクタリング）します。

最終コード

ここまで学んだ「責務の分割」「状態遷移」「継承」をすべて盛り込んだ、実際に遊べる完成版のコードです。どの部分がこれまで説明した内容に対応しているか、確認しながら読んでみてください。

Python
import pyxel
import random

# --- 1. 共通クラス (継承元) ---
class Character:
    def __init__(self, x, y, speed, hp):
        self.x = x
        self.y = y
        self.w = 8
        self.h = 8
        self.speed = speed
        self.hp = hp

    def draw(self, color):
        pyxel.rect(self.x, self.y, self.w, self.h, color)

# --- 2. Playerクラス (Characterを継承) ---
class Player(Character):
    def __init__(self, x, y):
        # 親クラスの初期化を呼び出す
        super().__init__(x, y, speed=2, hp=3)

    def move(self):
        if pyxel.btn(pyxel.KEY_LEFT) or pyxel.btn(pyxel.KEY_A):
            self.x = max(self.x - self.speed, 0)
        if pyxel.btn(pyxel.KEY_RIGHT) or pyxel.btn(pyxel.KEY_D):
            self.x = min(self.x + self.speed, 160 - self.w)
        if pyxel.btn(pyxel.KEY_UP) or pyxel.btn(pyxel.KEY_W):
            self.y = max(self.y - self.speed, 0)
        if pyxel.btn(pyxel.KEY_DOWN) or pyxel.btn(pyxel.KEY_S):
            self.y = min(self.y + self.speed, 120 - self.h)

    def update(self):
        self.move()

    def draw(self):
        super().draw(11) # 緑色で描画

# --- 3. Enemyクラス (Characterを継承) ---
class Enemy(Character):
    def __init__(self, x, y):
        super().__init__(x, y, speed=1, hp=1)

    def update(self):
        self.y += self.speed

    def draw(self):
        super().draw(8) # 赤色で描画

# --- 4. Bulletクラス ---
class Bullet:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        self.w = 2
        self.h = 4
        self.speed = 4

    def update(self):
        self.y -= self.speed

    def draw(self):
        pyxel.rect(self.x, self.y, self.w, self.h, 10) # 黄色

# --- 5. GameMasterクラス (全体管理) ---
class GameMaster:
    def __init__(self):
        pyxel.init(160, 120, title="Shooting Game")
        self.reset_game()
        pyxel.run(self.update, self.draw)

    def reset_game(self):
        self.game_state = "TITLE"
        self.player = Player(76, 100)
        self.enemies = []
        self.bullets = []
        self.score = 0

    def update(self):
        # 状態による分岐
        if self.game_state == "TITLE":
            if pyxel.btnp(pyxel.KEY_SPACE):
                self.game_state = "PLAY"

        elif self.game_state == "PLAY":
            self.update_play()

        elif self.game_state == "GAMEOVER":
            if pyxel.btnp(pyxel.KEY_SPACE):
                self.reset_game()

    def update_play(self):
        # プレイヤーの更新
        self.player.update()

        # 弾の発射
        if pyxel.btnp(pyxel.KEY_SPACE):
            self.bullets.append(Bullet(self.player.x + 3, self.player.y))

        # 敵のランダム生成
        if pyxel.frame_count % 30 == 0:
            ex = random.randint(0, 160 - 8)
            self.enemies.append(Enemy(ex, -10))

        # 弾の更新と削除
        for bullet in self.bullets[:]:
            bullet.update()
            if bullet.y < -10:
                self.bullets.remove(bullet)

        # 敵の更新と削除
        for enemy in self.enemies[:]:
            enemy.update()
            if enemy.y > 120:
                self.enemies.remove(enemy)

        # 当たり判定
        self.check_collision()

        # ゲームオーバー判定
        if self.player.hp <= 0:
            self.game_state = "GAMEOVER"

    def check_collision(self):
        # 弾と敵
        for enemy in self.enemies[:]:
            for bullet in self.bullets[:]:
                if (bullet.x < enemy.x + enemy.w and
                    bullet.x + bullet.w > enemy.x and
                    bullet.y < enemy.y + enemy.h and
                    bullet.y + bullet.h > enemy.y):

                    if bullet in self.bullets:
                        self.bullets.remove(bullet)
                    enemy.hp -= 1

                    if enemy.hp <= 0:
                        if enemy in self.enemies:
                            self.enemies.remove(enemy)
                        self.score += 10

        # プレイヤーと敵
        for enemy in self.enemies[:]:
            if (self.player.x < enemy.x + enemy.w and
                self.player.x + self.player.w > enemy.x and
                self.player.y < enemy.y + enemy.h and
                self.player.y + self.player.h > enemy.y):

                self.player.hp -= 1
                self.enemies.remove(enemy)

    def draw(self):
        pyxel.cls(0)

        if self.game_state == "TITLE":
            pyxel.text(55, 50, "SHOOTING GAME", 7)
            pyxel.text(45, 70, "PRESS SPACE TO START", 5)

        elif self.game_state == "PLAY":
            self.player.draw()
            for bullet in self.bullets:
                bullet.draw()
            for enemy in self.enemies:
                enemy.draw()

            # UI描画
            pyxel.text(5, 5, f"SCORE:{self.score}", 7)
            pyxel.text(120, 5, f"HP:{self.player.hp}", 8)

        elif self.game_state == "GAMEOVER":
            pyxel.text(60, 50, "GAME OVER", 8)
            pyxel.text(45, 70, "PRESS SPACE TO RESTART", 5)

# ゲーム起動
if __name__ == "__main__":
    game = GameMaster()
